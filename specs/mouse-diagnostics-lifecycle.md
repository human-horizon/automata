# Жизненный цикл диагностики мыши

## Контекст

В `internal/ui/context_panel.go` и `internal/ui/container.go` каждый mouse event
безусловно и синхронно дописывается в фиксированные файлы
`/tmp/context-mouse.log` и `/tmp/container-mouse.log`. При включённом all-motion
это создаёт большие журналы: за один прогон зафиксировано соответственно 5 305 и
77 111 строк. Пути имеют фиксированные права `0644`, ошибки записи игнорируются,
а потребителя этой диагностики в продукте нет.

Такая запись не должна быть обязательной частью обработки событий мыши: она
создаёт лишний синхронный I/O и не даёт функциональной ценности. При этом уже
существующие временные файлы нельзя удалять или переносить во время работы
приложения.

## Цель

Убрать безусловную синхронную запись каждого mouse event в фиксированные
`/tmp/context-mouse.log` и `/tmp/container-mouse.log`, не изменяя поведение мыши,
маршрутизацию панелей, watcher error logging и включение `tea.WithMouseAllMotion`.

## Что изменится

1. `internal/ui/context_panel.go` — удалить безусловное синхронное добавление
   каждого mouse event в `/tmp/context-mouse.log`; сохранить обработку событий,
   маршрутизацию панели и watcher error logging.
2. `internal/ui/container.go` — удалить безусловное синхронное добавление каждого
   mouse event в `/tmp/container-mouse.log`; сохранить обработку событий и
   `tea.WithMouseAllMotion`.

## Детали реализации

1. Не выполнять открытие, создание или добавление в
   `/tmp/context-mouse.log` и `/tmp/container-mouse.log` в обработчиках событий
   мыши. В частности, не оставлять синхронные вызовы `OpenFile` для этих путей.
2. Не удалять и не переносить уже существующие `/tmp`-файлы во время работы
   приложения. Очистка логов и миграция файлов не входят в задачу.
3. Сохранить текущую семантику mouse events, включая `tea.WithMouseAllMotion`,
   порядок обработки и маршрутизацию событий в активную панель.
4. Сохранить существующее логирование ошибок watcher-а; удаление диагностики
   мыши не должно менять обработку или видимость этих ошибок.
5. Проверить отсутствие новых записей статической проверкой либо тестом с
   внедряемым writer/перехватом I/O, не добавляя побочных записей в фиксированные
   `/tmp`-пути.
6. После реализации выполнить адресную Go-проверку затронутых пакетов, полный
   набор Go-проверок проекта и scoped `git diff --check`.

## Критерии приёмки

- [ ] В `context_panel.go` и `container.go` нет безусловного синхронного
      добавления каждого mouse event в фиксированные `/tmp`-файлы.
- [ ] На mouse events не создаются новые записи в
      `/tmp/context-mouse.log` и `/tmp/container-mouse.log`; для этого есть
      статическая регрессия или тест с внедряемым writer.
- [ ] В runtime-коде нет вызовов `OpenFile` для указанных `/tmp`-путей.
- [ ] Поведение mouse events и `tea.WithMouseAllMotion` не изменилось.
- [ ] Маршрутизация событий в панели не изменилась.
- [ ] Существующее логирование ошибок watcher-а сохранено.
- [ ] Runtime не удаляет и не переносит существующие `/tmp`-файлы.
- [ ] Адресные Go-тесты затронутых пакетов проходят.
- [ ] Полная проверка Go-проекта проходит.
- [ ] Scoped `git diff --check` проходит.
- [ ] Не изменены mouse semantics, shortcuts `F5/F7`, TypeScript и очистка
      логов.

## Явно исключено

Изменение семантики мыши, shortcuts `F5/F7`, TypeScript, удаление или миграция
существующих `/tmp`-логов, а также любые другие способы очистки логов требуют
отдельной спецификации.

## Состояние

Спецификация одобрена; runtime- и test-реализация выполнены в указанном scope.
