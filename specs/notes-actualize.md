# Actualize заметок проекта

## Контекст

`internal/ui/context_panel.go` показывает заметки проекта и поддерживает Copy/Paste. `memory.NoteSummary`/`NoteSection`, `memory.Read`/`Write` и `paths.DomainDir` задают действующую модель хранения. В Go-коде нет отдельного программного API модели; установленный Pi CLI документирует неинтерактивный режим `pi --print`, настройки и авторизацию из обычного Pi agent directory. `App.piLaunch` задаёт profile и `PI_CODING_AGENT_DIR` для интерактивных сессий.

## Цель

Добавить явную кнопку Actualize для консолидации Notes только текущего profile/domain. После успешной AI-консолидации результат заменяет существующий `notes.json`; ошибка, конфликт параллельной записи или провал проверки не меняют исходные Notes. Предусмотреть резервную копию и Undo.

## Границы

- Не менять Tree, Kanban, job lifecycle, Pi terminal emulation, публичную схему notes или реальные пользовательские Notes при разработке/тестировании.
- Не отправлять AI-запрос до явного нажатия Actualize; обработка может вызвать платный выбранный в Pi провайдер.
- Не выполнять автоматическое сжатие/обрезание записей для подгонки контекста.
- Активный формат результата — массив `NoteSummary` с `Sections`; legacy `Notes` продолжает читаться.

## Что изменится

1. `internal/ai-knowledge/notesactualize/` — сервис консолидации, runner `just --print`, чтение разрешённых настроек модели/уровня размышления, chunking, проверка схемы и смысловой аудит; зависимости для HTTP/AI не добавляются.
2. `internal/ai-knowledge/memory/reader.go` и тесты — безопасные Notes snapshot/replacement/backup/Undo primitives, не меняющие текущий формат и использующие существующий atomicfile.
3. `internal/ui/context_panel.go`, `internal/ui/notes_actualize.go` и тесты — кнопка, селекторы модели/уровня размышления, async-состояние, scoped results, запуск/Undo и обновление панели.
4. `main.go` — передача `just` executable, Pi agent directory и конфигурационного источника в сервис.
5. `specs/notes-actualize.md`, `CONTEXT.md` — контракт, ограничения и результаты проверок.

## AI runner и стоимость

- Запускать настроенную команду `just` как отдельный неинтерактивный процесс через `exec.CommandContext`, без shell; базовый режим — `just --print --mode text --no-session --no-tools --no-mcp --no-extensions --no-context-files --no-skills --no-prompt-templates --no-approve`.
- Передавать Pi agent directory из `App.piAgentDir` и канонические `AI_PROFILE`/`AUTOMATA_PROFILE`/`AI_DATA_HOME` текущего Automata profile. Не передавать секреты в аргументах и не сохранять их.
- Читать только `enabledModels`, `defaultModel` и `defaultThinkingLevel` из `settings.json` активного Pi agent directory. Список моделей в селекторе берётся только из `enabledModels`; начальные значения — `defaultModel` и `defaultThinkingLevel`. Если default model отсутствует в enabled list, выбрать первый включённый вариант. Пустой/некорректный список блокирует запуск и показывает ошибку. Не менять `settings.json`.
- Перед запуском Actualize показать пользователю выпадающие списки модели и уровня размышления; первоначальные значения берутся из настроек, выбор действует только на этот запуск и не записывается в настройки.
- Передавать выбранные значения в CLI как `--model <enabled-model-id>` и `--thinking <level>`. Допустимые уровни: `off`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`.
- Subprocess и платные запросы начинаются только после явного подтверждения запуска в селекторе Actualize. Ошибка отсутствующего `just`, настроек или авторизации показывается как Failed без изменения Notes.
- Каждый вызов ограничен трёхминутным timeout. `just` запускается в собственной process group; при отмене/timeout вся группа получает SIGTERM, затем SIGKILL после ограниченного grace period. `WaitDelay` ограничивает ожидание унаследованных stdout/stderr pipes, чтобы wrapper-child не мог навсегда удержать UI в Working.
- Подтверждение запуска обязательно; временные логи Actualize и LOG UI удалены по решению пользователя.
- Process lifecycle test запускает изолированный fake-wrapper с дочерней командой, проверяет bounded timeout/cancel и отсутствие дочернего side effect после остановки; никаких настоящих Pi/API/Notes.
- Просить модель вернуть только JSON-массив существующей структуры; строгий decoder отклоняет Markdown fences, trailing data, пустой/некорректный результат и неизвестные публичные поля.

## Обработка больших Notes

- Сначала посчитать размер сериализованных заметок; не передавать весь файл одним prompt при превышении budget.
- Все Notes текущего snapshot передаются одним вызовом консолидации, если сериализованный вход помещается в установленный безопасный предел. Если предел превышен, завершить до AI-запроса; не дробить заметки и не обрезать содержимое.
- До записи проверять только технический JSON/schema контракт; отдельный AI semantic-review по решению пользователя не вызывается.
- Вход выше 2 MiB отклоняется до запроса, не обрезается и не делится на группы. Консолидация — один запрос модели; отдельный semantic-review отключён решением пользователя. Actualize по-прежнему может тарифицироваться провайдером.

## Сервис и проверки результата

- Вход сервиса: immutable snapshot `{profile, domain, notes}` и интерфейс `ModelRunner`; production adapter — Pi CLI, tests используют deterministic fake.
- Системная инструкция требует объединять повторы и историю, сохранять актуальную архитектуру, решения и причины, конкретные настройки/контракты, фактические проверки, ограничения, блокеры, открытые задачи и различия local/production. При неразрешимом противоречии формулировать неопределённость; не выдумывать факты.
- Генерировать тематические заголовки, а не даты. Не дублировать смысл одновременно в `Notes` и `Sections`.
- До записи проверить JSON/schema, лимиты/непустые заголовки и отсутствие пустого результата при существенном исходнике. Отдельный AI semantic-review отключён по решению пользователя; формально валидный результат может содержать смысловые пропуски, не обнаруженные технической валидацией. Undo восстанавливает исходные байты, если результат не редактировался.

## Безопасная публикация и Undo

- До запроса AI взять исходный snapshot и SHA-256 исходных байтов `notes.json`; отсутствующий файл различать от пустого.
- Резервировать точные исходные байты в приватном каталоге внутри `paths.DomainDir(profile, domain)` (каталог `0700`, файлы `0600`). Резервные версии сохранять до пяти; очистка не должна удалять единственную копию оригинала до успешной atomic replacement.
- Перед записью повторно прочитать Notes и сравнить fingerprint с исходным. Несовпадение означает conflict: отбрасывать AI-ответ, оставлять новые Notes без изменений и сообщать пользователю.
- Публиковать только через `memory.Write`/существующий atomicfile путь после проверок. Инвалидация reader cache и UI refresh происходят только после commit.
- `Undo last Actualize` доступен после успешного commit, восстанавливает точные исходные bytes через ту же приватную backup/atomic-write систему, после проверки, что текущий файл всё ещё соответствует результату Actualize. При последующем редактировании Undo отказывает, не затирая его. Backup не удаляется до подтверждённого восстановления.
- Per-domain in-process guard запрещает параллельные Actualize; generation token привязывает async результат к profile/domain. Дополнительно перед записью действует fingerprint check. Изменения через другие процессы, случившиеся до повторного чтения, fail closed. Общая файловая блокировка для всех независимых внешних writers не заявляется.

## UI

- Toolbar Notes получает кнопку `Actualize`, на узкой панели — краткую подпись/иконку, существующие Copy/Paste и hit-testing сохраняются.
- Нажатие Actualize открывает настройки запуска с выпадающими списками `enabledModels` и уровня размышления; явная команда запуска подтверждает списки и только затем вызывает `just --print`.
- Длительные AI calls выполняются в `tea.Cmd`; `Update` не блокируется.
- Состояния: Ready, Actualizing…, Completed (число заметок до/после), Failed (ошибка без потери исходника), Undo last Actualize.
- Во время работы запрещён повторный запуск для того же domain; можно безопасно переключить проект. Поздний ответ применяется только к исходному profile/domain и никогда к новому активному проекту.
- После commit инвалидировать `CachedReader`, перечитать активный домен только если он всё ещё тот же; иначе watcher обновит его при возвращении.

## Проверки

- Unit-тесты используют mock `ModelRunner`, временные каталоги и детерминированные ответы; никаких реальных API/пользовательских файлов.
- Покрыть дедупликацию и цепочки исправлений, причины решений, устаревший блокер, открытые задачи, local/production, malformed/unsupported AI output, semantic audit rejection, запись/backup failure, конкурентное изменение, Undo, переключение проекта, duplicate guard и повторную идемпотентную консолидацию.
- Проверить race для сервиса/backup/guard и UI generation; полный `go test ./...`, `go test -race ./...`, `go vet ./...`, golangci-lint, build и diff checks.
- В финальном аудите сравнить hash/mtime реальных project `notes.json` до/после разработки: файлы не должны измениться.

## Статус

По решению пользователя Actualize отправляет все Notes одним вызовом и применяет его результат после технической проверки JSON/schema, размера, fingerprint, backup и atomic commit. Semantic review и полное временное логирование удалены; повторных model calls нет. Возможные смысловые omissions автоматически не обнаруживаются; Undo сохраняет путь восстановления исходных bytes при отсутствии последующих правок.
