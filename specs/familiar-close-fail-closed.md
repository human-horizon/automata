# Безопасное закрытие familiar и внешнее удаление

## Контекст

Закрытие familiar запускает остановку Pi jobs, останавливает эмулятор, обновляет runtime state, удаляет запись из `familiars.json` и удаляет JSONL. Сейчас ожидание остановки jobs вызывается синхронно из Bubble Tea update flow; при ошибке возможна частично завершённая очистка.

## Контракт закрытия пользователем

1. Проверить, что `familiarID` является дочерней сессией активного owner, и подготовить планы остановки всех jobs без отправки сигналов.
2. Выполнить все job stops с существующими проверками process identity. Если подготовка или остановка завершилась ошибкой, не менять реестр, JSONL, кэш/active-session state и таб. Ошибка видна в UI; остановленные ранее jobs могут оставаться остановленными.
3. Атомарно удалить запись из `familiars.json`. Ошибка до atomic commit сохраняет JSONL и таб. Ошибка после commit считается committed cleanup warning.
4. После commit остановить familiar emulator, очистить его runtime/cache state и удалить JSONL, если файл существует.
5. Ошибка очистки после commit не возвращает familiar в реестр: таб удаляется, состояние памяти приводится к committed состоянию, а предупреждение показывается пользователю.

## Контракт внешнего удаления

- Реестр уже изменён внешним процессом. Перед остановкой runtime подготовить и выполнить fail-closed job shutdown.
- При ошибке job shutdown сохранить familiar tab, emulator/cache state и JSONL, показать предупреждение. Не пытаться восстановить внешний реестр.
- При успешной остановке удалить runtime/cache state и таб. Не удалять JSONL и не переписывать реестр.

## Асинхронность

Ожидание process termination выполняется в `tea.Cmd`. Команда работает с захваченными идентификаторами/планом и не меняет `App`, `Tree` или `ChatPanel`. UI state обновляется только из completion message в Bubble Tea update loop. Пока операция выполняется, повторное закрытие/cleanup того же familiar игнорируется.

## Обратная совместимость

- Не менять поведение session manifest v0 и не мигрировать legacy sessions автоматически.
- Сохранять текущие проверки владения session ID и process identity.
- Для отсутствующего registry entry или JSONL сохранять существующую семантику уже очищенного состояния.

## Проверки приёмки

- Регрессионные тесты проверяют порядок: job stop → registry commit → emulator/cache cleanup → JSONL cleanup.
- Ошибки preflight/job stop не удаляют запись реестра, JSONL, таб или runtime state.
- Ошибка до registry commit сохраняет таб и историю; post-commit ошибка даёт committed warning и удаляет таб.
- Внешнее удаление не удаляет JSONL; неудачный job stop сохраняет таб и emulator.
- Тест с блокирующим fake job stop доказывает, что `Update` быстро возвращает `tea.Cmd`, а completion обрабатывается отдельно.
- `go test ./internal/ui ./...` и тесты `main` покрывают новые переходы состояний; `go test -race ./...` проверяет отсутствие гонок.
