# Исправление запуска pi после Clear

## Контекст

При нажатии `Clear` Automata удаляет историю текущей сессии и создаёт новый эмулятор `pi`. Для профиля `just` команда запускается напрямую через `/usr/local/bin/pi`, а путь к каталогу агента передаётся переменной `PI_CODING_AGENT_DIR=/Users/a/.ai/just/pi`.

Обычное открытие чата запускает эмулятор через `StartWithEnv`, но сценарий `Clear` вызывает только `Start`. Поэтому после очистки новый процесс `pi` стартует без `PI_CODING_AGENT_DIR` и не использует `~/.ai/just/pi`.

## Цель

После `Clear` автоматически перезапускать чат с тем же идентификатором сессии и сохранять тот же каталог агента `~/.ai/just/pi`, не меняя поведение обычного открытия чата.

## Что изменится

1. `main.go` — синхронно запускать новый PTY через `StartSync` с переменными окружения, подготовленными `createChatEmulator`, внутри `clearSessionCmd`; возвращать `PtyReadyMsg`, чтобы основной цикл автоматически начал `Listen`.
2. `main_test.go` или отдельный тестовый файл пакета `main` — добавить регрессионную проверку, что сценарий Clear передаёт `PI_CODING_AGENT_DIR` и возвращает сигнал перезапуска.
3. `CONTEXT.md` — записать проблему и решение.

## Детали реализации

1. Оставить единую функцию `createChatEmulator`, формирующую команду и окружение для чата.
2. После создания нового эмулятора в `clearSessionCmd` запускать его через `StartSync`, используя подготовленное окружение.
3. Возвращать `portalis.PtyReadyMsg` только после успешного запуска; обработчик сообщений Automata продолжит чтение PTY через `Listen`.
4. Для `PI_CMD` и терминалов сохранить существующее поведение: пустое дополнительное окружение допустимо.
5. Регрессионный тест должен проверять передачу `PI_CODING_AGENT_DIR` и сигнала автоматического перезапуска, не требуя реального API-модели.

## Критерии приёмки

- [x] Новый процесс `pi` получает `PI_CODING_AGENT_DIR=/Users/a/.ai/just/pi` при стандартном запуске Automata.
- [x] После `Clear` сохраняется тот же `--session-id`.
