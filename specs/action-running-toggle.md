# Подсветка и остановка выполняющихся Actions

## Контекст

Кнопки Actions в KnowledgePanel запускают команду после подтверждения, но сама кнопка не отражает, что команда ещё работает. Остановить такую команду из панели нельзя.

## Цель

Пока команда выполняется, подсвечивать соответствующую кнопку. Повторное нажатие на эту кнопку останавливает её команду.

## Что изменится

1. `internal/ui/actions_runner.go` и `actions_runner_test.go` — добавить отмену процесса команды с завершением его дочерних процессов.
2. `internal/ui/knowledge_actions.go` и `knowledge_panel.go` — отслеживать активные запуски, обрабатывать повторное нажатие и показывать состояние выполнения.
3. `internal/ai-knowledge/ui/render.go` и профильные тесты — визуально выделять работающие кнопки.
4. `internal/ui/knowledge_panel_test.go` — проверить запуск, подсветку, отмену, завершение и ошибки.
5. `CONTEXT.md` — записать поведение и результаты проверок.

## Детали реализации

1. Для неработающей кнопки сохранить текущий сценарий: клик открывает подтверждение, и команда начинается только после подтверждения.
2. Работающую кнопку показывать заметным активным стилем темы: жирный текст цвета `Success` и отдельный индикатор выполнения.
3. Повторный клик по работающей кнопке сразу отменяет её запуск, не открывая подтверждение. Подсветка снимается после завершения процесса. Отдельная постоянная строка Action-статуса в правой панели не отображается.
4. Привязывать запуски к профилю, папке и ID действия. Разные Actions могут выполняться одновременно; повторное нажатие останавливает только соответствующий запуск. Переход между панелями или папками не должен незаметно терять возможность остановить команду; при возврате в исходную папку активная кнопка остаётся подсвеченной.
5. Передавать runner-у `context.Context`. Команду запускать в отдельной Unix process group; при отмене отправить группе `SIGTERM`, а оставшиеся процессы завершить `SIGKILL` после ограниченного grace period. Закрытие KnowledgePanel отменяет все принадлежащие ей активные запуски.
6. Существующую асинхронность Bubble Tea, подтверждение точной команды и отображение ошибок сохранить.
7. Тестировать отмену через подменённый runner и не выполнять реальные пользовательские команды.

## Критерии приёмки

- [x] Работающая Action кнопка визуально отличается от неработающих.
- [x] Повторный клик по работающей кнопке отменяет только её запуск без повторного подтверждения.
- [x] До подтверждения команда не запускается; одиночный запуск и отображение его ошибок сохраняются.
- [x] При отмене кнопка остаётся активной до завершения runner-а, затем снимается подсветка; постоянная строка Action-статуса не занимает правую панель.
- [x] Несколько разных Actions могут выполняться независимо; активное состояние корректно сохраняется при переключении контекста.
- [x] Закрытие панели отменяет принадлежащие ей активные команды.
- [x] Тесты Actions, форматирование, линтер, `go vet`, полный Go suite и race suite проходят; E2E-пакет входит в `go test ./...` и прошёл.
- [x] `CONTEXT.md` и `git diff --check` актуальны; коммит не создаётся.

Примечание: тест `TestRunShellActionCancelStopsProcessGroup` запускает локальный `sleep` в собственной временной папке. Это служебная тестовая команда, не пользовательская.
