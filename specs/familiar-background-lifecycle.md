# Жизненный цикл фоновых фамильяров

## Контекст

Эмулятор фамильяра хранится в `familiarEmulatorCache`, а маршрутизация PTY-сообщений в `App.routeCachedEmulatorMessage` проверяет только `emulatorCache`. После смены активной панели сообщения PTY старого фамильяра поэтому не доходят до его эмулятора, цепочка `Listen` прекращается, а фоновой процесс может зависнуть. При повторном открытии чата `createFamiliarEmulator` также создаёт новый эмулятор вместо уже работающего кэшированного экземпляра.

## Цель

Сохранить работу фамильяров независимо от фокуса ChatPanel и возвращать при повторном открытии чата тот же кэшированный эмулятор, не создавая дубликатов. Явное закрытие фамильяра и `Clear` должны по-прежнему останавливать эмуляторы и удалять соответствующие кэши.

## Что изменится

1. `main.go` — маршрутизация PTY-сообщений через `emulatorCache` и `familiarEmulatorCache`; переиспользование существующего familiar-эмулятора в `createFamiliarEmulator`.
2. `main_view_test.go` — регрессионные тесты фоновой маршрутизации PTY и повторного использования кэшированного familiar-эмулятора.

## Детали реализации

1. В `routeCachedEmulatorMessage` определить `SessionID` для PTY-сообщений как сейчас.
2. Найти эмулятор с этим идентификатором сначала в обычном кэше, затем в кэше фамильяров. Если найден ненулевой указатель и сообщение не является завершением familiar PTY, напрямую передать сообщение через `em.Update(msg)` и вернуть обработанную команду.
3. Для `PtyExitMsg` familiar удалить запись из `familiarEmulatorCache` и, если она есть, из `activeSessions`; обновить состояние дерева при наличии дерева. Вернуть это сообщение в обычную маршрутизацию Warp, чтобы активный `ChatPanel` сохранил удаление вкладки и polling.
4. Если идентификатор неизвестен обоим кэшам или значение равно `nil`, оставить сообщение для обычной маршрутизации Warp.
5. В `createFamiliarEmulator` после инициализации кэша проверить существующий ненулевой эмулятор по `sessionID`. Вернуть его и сохранённое окружение без создания нового экземпляра.
6. Для нового эмулятора сохранить текущую настройку команды, окружения, scrollback и запись в `familiarEmulatorCache`.
7. Не менять обработчики явного закрытия фамильяра и `Clear`: они должны и дальше вызывать `Stop` и удалять записи из обоих кэшей.

## Критерии приёмки

- [ ] PTY-сообщения фамильяра из `familiarEmulatorCache` обрабатываются, когда его ChatPanel не активен.
- [ ] При повторном создании вкладки работающего фамильяра возвращается тот же указатель `*portalis.Emulator` из кэша.
- [ ] После `PtyExitMsg` familiar удаляется из кэша, а повторное создание даёт новый эмулятор.
- [ ] Цепочка `Listen` продолжает обрабатывать сообщения после смены активного чата.
- [ ] `PtyExitMsg` активного familiar остаётся доступным `ChatPanel` для удаления вкладки и следующего polling.
- [ ] Неизвестные PTY-сообщения по-прежнему передаются обычной маршрутизации Warp.
- [ ] Явное закрытие и `Clear` останавливают фамильяры и удаляют их записи из кэшей.
- [ ] Все адресные и полные Go-проверки проходят без изменений публичной семантики закрытия/Clear.
