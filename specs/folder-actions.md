# Действия текущей папки (Actions)

## Контекст

Ссылки на локальные приложения и dev-серверы теряются в истории чата и выводе инструментов. Нужны постоянные кнопки, которые агент добавляет для текущей папки, а пользователь запускает из правой панели.

## Цель

Добавить сворачиваемую секцию `Actions` в KnowledgePanel между `Status` и остальными разделами. Агент регистрирует кнопку с названием и произвольной системной командой; команда запускается только после явного пользовательского подтверждения с показом точной команды и рабочего каталога.

## Что изменится

1. `just/pi/extensions/automata/index.ts` и `index.test.mjs` — добавить агентский tool `add_action`, записывающий или обновляющий действие текущего folder-domain.
2. `internal/ai-knowledge/actions/reader.go` и тесты — типизированная загрузка и валидация folder-scoped записей.
3. `internal/ai-knowledge/ui/render.go` и тесты — отрисовка секции `Actions` и списка кнопок.
4. `internal/ui/knowledge_panel.go` и тесты — domain watcher, сворачивание, обработка кликов, confirmation UI и неблокирующий запуск команды.
5. `CONTEXT.md` — записать реализацию, контракт безопасности и результаты проверок.

## Детали реализации

### Область данных и регистрация агентом

- Область — текущий профиль и folder-domain активной Pi-сессии; все чаты одного domain видят общий список. Данные сессии и соседних folder-domains не смешиваются.
- Файлы действий хранятся в `profiles/<profile>/domains/<domain>/actions/`. Каждое действие — отдельный JSON-файл с 64-символьным lowercase SHA-256 ID, названием, командой и абсолютным рабочим каталогом. Чтение принимает только regular files и реальные каталоги; повреждённые записи диагностируются, не скрывая остальные валидные действия. Записи одного имени (без учёта регистра после Unicode NFC-нормализации) обновляют прежнюю кнопку, не создавая дубликат.
- `add_action({name, command})` берёт domain/session/profile из текущего `ExtensionContext`, а рабочий каталог — из `ctx.cwd`; произвольный путь через параметры tool не принимается. Имя и команда валидируются, `ctx.cwd` должен быть абсолютным существующим каталогом.
- Регистрация только сохраняет запись: она никогда не запускает команду. Каталоги имеют приватные права, файл записывается атомарно; ошибка чтения/декодирования существующей записи не должна молча затирать данные.
- Записи folder-domain переживают перезапуск и Clear отдельного чата; при rename/move переносятся вместе с domain-каталогом.

### Панель и запуск

- Секция расположена сразу после `Status` и до `Task`, `Plans` и `Jobs`. Заголовок `Actions` сворачивается тем же мышиным паттерном, что `Plans`/`Jobs`; список показывает названия сохранённых действий.
- Клик по кнопке открывает подтверждение с её названием, полной командой и рабочим каталогом. Отмена (`Esc`, Cancel или клик вне диалога) не запускает процесс. UI-копия команды экранирует терминальные управляющие символы, исполняемая команда при этом остаётся точной.
- Только подтверждение запускает сохранённую строку как `/bin/sh -c <command>` в сохранённом `ctx.cwd`. Поддерживаемые Automata платформы — macOS и Linux. Запуск выполняется через `tea.Cmd`, не блокирует Bubble Tea `Update`; результат/ошибка возвращается typed message и отображается в панели.
- UI читает только записи текущего `profile`/`domain`, обновляет список по fsnotify, игнорирует устаревшие watcher events и освобождает watcher при смене domain/deactivation.
- Commands не извлекаются автоматически из logs/job output. Доступен только пользовательский путь: агент сохраняет действие, пользователь подтверждает его запуск.

- Pi Automata: targeted Node suite — 15/15; `pnpm exec tsc --noEmit` прошёл.
- Go: `go mod verify`, `gofmt`, `go vet ./...`, golangci-lint (0 issues), полный `go test ./... -count=1 -p 1`, `go test -race ./internal/... . -count=1 -p 1`, host build и macOS/Linux cross-build прошли.
- Две `-trimpath -buildvcs=false` сборки совпали: SHA-256 `553e8e86714cf2f18c84f2c477ae870cdf2dd420ac14412fafe2e8195b29b92d`.
- Govulncheck не нашёл уязвимостей, вызываемых кодом; одна уязвимость найдена только в требуемом модуле, без обнаруженного вызова из кода.
- Полный E2E suite прошёл. Отдельный self-building `TestRootChatSessionID` один раз не дождался prompt, независимый повтор прошёл за 4.15s; тест остаётся timing-sensitive.

## Критерии приёмки

- [x] `add_action` сохраняет кнопку только в текущем folder-domain; пустые/невалидные параметры и невалидный cwd дают ошибку без частичной записи.
- [x] Повторная регистрация имени обновляет действие атомарно; команда не запускается во время регистрации.
- [x] Automata читает валидные записи текущего domain, изолирует профили/папки и безопасно сообщает о повреждённых данных.
- [x] `Actions` отображается сразу под `Status`, сворачивается, имеет корректные row hitboxes и обновляется от watcher event.
- [x] До подтверждения и при отмене runner не вызывается; подтверждение передаёт runner точные command/cwd, а его ошибки видны в UI.
- [x] Выполнение идёт вне `App.Update`; tests используют injected runner и не запускают реальные системные команды.
- [x] Clear чата не удаляет folder actions; rename/move сохраняет их вместе с folder-domain.
- [x] Pi: targeted Automata Node tests с `env -u AI_PROFILE`, `pnpm exec tsc --noEmit`; Go: focused tests, `gofmt`, `go vet`, lint и полный CI-equivalent test/race/E2E/build gate согласно `CONTRIBUTING.md`/README.
- [x] `CONTEXT.md`, newline/trailing-whitespace и `git diff --check` актуальны; коммит не создаётся.
