# Секции notes и Markdown в Automata

## Контекст

Сейчас long-term notes хранятся в `notes.json` как массив объектов `{title, notes: string[]}`. API расширения называет операцию чтения `read_knowledge`, а Automata показывает notes как обычный список строк без структуры и форматирования.

Нужно разделить семантику API и UI: API работает с notes, UI-панель по-прежнему называется Knowledge. Содержимое notes должно группироваться по секциям и поддерживать Markdown.

## Цель

Добавить секции в формат `notes.json`, сделать `read_notes` каноническим API чтения notes, сохранить чтение старого формата и отображать содержимое секций в ContextPanel с Markdown-форматированием. В UI каждая заметка остаётся одной сворачиваемой секцией; внутренние секции не становятся отдельными интерактивными строками.

## Формат данных

Новый note хранится так:

```json
{
  "title": "Название заметки",
  "sections": [
    {
      "title": "Архитектура",
      "content": "**Ключевое решение**\n\n- Первый пункт\n- Второй пункт"
    }
  ]
}
```

- `sections` — отдельное поле JSON и массив секций в исходном порядке.
- `Section.title` — заголовок секции.
- `Section.content` — единая Markdown-строка; переносы, пустые строки и fenced code blocks сохраняются.
- Старый формат `{title, notes: string[]}` обязателен к чтению без миграции и записи обратно.
- Для старого формата reader создаёт внутреннюю секцию без заголовка, объединяя строки через `\n`; UI продолжает показывать их как читаемый список.
- Новые записи через API используют `sections`. Старое поле `notes` остаётся принимаемым для совместимости.

## API

1. В расширении Automata добавить тип `NoteSection` и расширить `Note` полем `sections`.
2. `read_notes` становится каноническим инструментом чтения. Он возвращает планы и notes в Markdown-тексте, где каждая note содержит список своих секций и Markdown-содержимое секций.
3. `read_knowledge` сохранить как совместимый deprecated-алиас с тем же результатом, чтобы старые Pi-сессии не ломались.
4. `add_note` и `edit_note` принимают `sections`; существующий параметр `notes` продолжает работать. При передаче `sections` запись хранится в новом формате, при передаче только `notes` — в старом совместимом формате.
5. Заголовки UI остаются `Knowledge`; это не переименовывает панель Automata.

## Markdown-рендеринг

В ContextPanel для каждой note отображается одна сворачиваемая секция:

1. В свернутом состоянии — заголовок note.
2. В раскрытом состоянии — заголовок каждой внутренней секции, если он задан.
3. Отформатированное содержимое секций в исходном порядке.

Внутренние секции не имеют отдельных маркеров, состояний раскрытия или интерактивных строк.

Рендерер должен поддерживать без показа исходных маркеров:

- заголовки;
- абзацы и переносы;
- маркированные и нумерованные списки;
- blockquote;
- fenced code block с языком;
- inline code;
- жирный и курсивный текст;
- Markdown-ссылки.

Неподдержанные конструкции остаются читаемым текстом. Ширина учитывается при переносе, существующая прокрутка и реактивный watcher `notes.json` сохраняются.

## Что изменится

1. `extensions/automata/index.ts` — типы notes/sections, операции `add_note`/`edit_note`, канонический `read_notes` и совместимый alias.
2. `extensions/automata/index.test.mjs` — проверки нового JSON-формата и API.
3. `internal/ai-knowledge/memory/reader.go` — модели секций, чтение нового и legacy форматов, нормализация.
4. `internal/ui/context_panel.go` — вывод секций и Markdown вместо списка сырых строк.
5. `internal/ui/markdown.go` — детерминированный терминальный Markdown-рендерер на существующем TUI-стеке.
6. Тесты memory/UI/Markdown — legacy-совместимость, секции, Markdown и переносы.
7. `CONTEXT.md` — запись о проблеме и решении после завершения.
