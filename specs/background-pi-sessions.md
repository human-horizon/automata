# Фоновая работа Pi-сессий

## Контекст

Каждый чат использует отдельный `portalis.Emulator`. Чтение PTY работает цепочкой: после `PtyOutputMsg` метод `Emulator.Update` возвращает следующий `Listen()`.

После переключения чата прежний `ChatPanel` удаляется из активного дерева Warp, но его emulator остаётся в `App.emulatorCache`. Сообщения прежней сессии проходят только через активное дерево Warp, не находят соответствующий emulator и теряются. Следующий `Listen()` не создаётся, очередь PTY заполняется, а `just-pi` блокируется на выводе.

## Цель

Pi-сессии продолжают выполнять инструменты и читать PTY-вывод независимо от того, какой чат открыт в интерфейсе.

## Что изменится

1. `main.go` — добавить маршрутизацию PTY-сообщений напрямую в cached emulator по `SessionID` до передачи сообщения в активное дерево Warp.
2. `main_view_test.go` или новый тест рядом с `main.go` — добавить регрессионные проверки маршрутизации активных и фоновых сессий.

## Детали реализации

1. Добавить функцию, извлекающую `SessionID` из:
   - `portalis.PtyReadyMsg`;
   - `portalis.PtyOutputMsg`;
   - `portalis.PtyExitMsg`.
2. В начале `App.Update` проверять PTY-сообщения:
   - если `SessionID` найден в `emulatorCache`, вызвать `em.Update(msg)` напрямую и вернуть полученную команду;
   - не передавать обработанное сообщение повторно через Warp;
   - если emulator не найден, оставить обычную маршрутизацию через Warp, чтобы не сломать `ContextPanel` и другие вложенные терминалы.
3. Не менять жизненный цикл процессов, кеширование emulator, переключение панелей и обработку пользовательского ввода.
4. Добавить тесты:
   - сообщение фоновой cached-сессии считается обработанным;
   - сообщение неизвестной сессии не перехватывается и остаётся доступным для Warp;
   - поддерживаются все три PTY-типа.
5. После изменения кода пересобрать используемый executable командой `go build -o automata .`; `go build ./...` только проверяет сборку пакетов и не обновляет файл `./automata`.
6. Проверить свежий executable сценарием из двух PTY-сессий: фоновая сессия должна вывести данных больше ёмкости очереди `64 × 4096` и завершить действие, пока открыт второй чат.

## Критерии приёмки

- [x] PTY-сообщение фонового чата попадает в его cached emulator.
- [x] После `PtyOutputMsg` команда следующего чтения не теряется.
- [x] Сообщения вложенных emulator, отсутствующих в `emulatorCache`, продолжают идти через Warp.
- [x] Переключение между чатами не останавливает работу `just-pi`.
- [x] `go test -count=1 ./...` проходит.
- [x] `go vet ./...` проходит без ошибок.
- [x] Используемый executable пересобран через `go build -o automata .`.
- [x] На свежем executable обе PTY-сессии завершили действие после переключения чата (`BACKGROUND_PROOF_OK`).
