# Безопасное переименование дерева Automata

## Статус
Реализовано по безопасной версии: после переименования остановленные процессы запускаются только при повторном выборе элемента.

## Контекст
Дерево Automata хранит виртуальные папки, чаты и терминалы. Имя элемента входит в session ID, поэтому простое изменение `Item.Name` оставляет связанные данные по старым путям. Сейчас контекстное меню умеет менять имя только в памяти дерева: не переносятся каталоги сессий, JSONL, notes, планы, status, jobs и Kanban, а работающие эмуляторы могут остаться привязанными к старому ID.

Папка может иметь `BoundPath`. Это только привязка к реальной директории: переименование элемента не должно менять имя реальной директории.

## Цель
Добавить безопасное переименование папок, чатов и терминалов через `F2` и контекстное меню с сохранением всех связанных данных, обновлением session ID и отказом при конфликте имён.

## Предлагаемое поведение активных сессий
- При переименовании папки остановить все работающие чаты и терминалы внутри неё, включая связанные familiars и jobs.
- При переименовании отдельного чата или терминала остановить только выбранный элемент и его familiars.
- После операции не запускать остановленные процессы автоматически. При следующем выборе элемента он запускается уже с новым session ID и продолжает перенесённый контекст.

Если вместо этого требуется автоматический запуск после переименования, этот раздел и критерии приёмки нужно изменить до начала реализации.

## Что изменится
1. `internal/tree/model.go` и `internal/tree/input.go` — единый безопасный rename-flow, проверка конфликтов, обработка ошибок в модальном окне и клавиша `F2`.
2. `main.go` — callback переименования, остановка затронутых эмуляторов/jobs/familiars, обновление кэшей и текущего session ID.
3. `internal/paths/sessionfile.go` — безопасные операции миграции session directory, JSONL-заголовка и familiars.
4. `internal/paths/paths.go` и/или `internal/kanban/kanban.go` — перенос доменов notes/Kanban без изменения содержимого.
5. Тесты `internal/tree`, `internal/paths`, `main_view_test.go` и при необходимости E2E — проверка UI, конфликтов, миграции, сохранности данных и повторного запуска.
6. `CONTEXT.md` — запись проблемы, решения и новых правил после завершения.

## Детали реализации

### 1. Проверка имени до изменения дерева
- Обрезать внешние пробелы; пустое имя отклонять.
- Проверять конфликт среди соседей независимо от типа элемента.
- Дополнительно проверять коллизию `slug.Slug`, поскольку разные отображаемые имена могут дать один session ID.
- При конфликте не менять дерево и файловую систему; модальное окно остаётся открытым и показывает понятную ошибку.
- Имя `BoundPath` не изменять.

### 2. Расчёт миграции
До изменения `Item.Name` построить список пар `старый ID → новый ID`:
- для переименованного чата/терминала — одна пара;
- для папки — все дочерние чаты и терминалы рекурсивно;
- для каждого затронутого folder domain — пара старого и нового domain пути.

Проверить, что ни один целевой session directory или domain directory не существует отдельно от соответствующего источника. Объединение каталогов запрещено.

### 3. Остановка
- Остановить эмуляторы из `emulatorCache` до перемещения данных.
- Удалить затронутые ID из `activeSessions` и обновить `Tree.SetActiveSessions`.
- Для каждого затронутого session ID остановить jobs через существующий механизм `ai-knowledge`/`jobs.KillSession`.
- Для каждого владельца familiars остановить эмуляторы familiars и удалить их старые ID из кэша/active set.
- Не удалять JSONL, notes, планы, status, jobs, Kanban или записи familiars.

### 4. Перенос данных
- Переместить каждый профильный `sessions/<session-id>/` со старого ID на новый. Это сохраняет `plans.json`, `status.json`, `settings.json`, `jobs/` и `familiars.json`.
- Для каждого найденного chat JSONL в выбранном `piAgentDir` атомарно обновить ID в первой JSON-строке с новым session ID. Содержимое истории и остальные строки не менять.
- Для familiars обновить `sessionId` владельца и каждого familiar с новым префиксом; перенести их session directories и обновить заголовки их JSONL.
- Для folder domains переместить каталоги `domains/<domain>/`, включая `notes.json` и `kanban/`, на новые domain пути. Содержимое файлов не изменять.
- При ошибке любого шага не менять имя дерева и не продолжать частичную миграцию; по возможности выполнить rollback уже перемещённых путей и показать ошибку.

### 5. Завершение и UI
- После успешной миграции изменить имя `Item`, пересобрать flat-список и сохранить `state.json`.
- Обновить `currentSessionID`, `emulatorCache`, `activeSessions` и watcher-ы под новые ID.
- Не оставлять текущую панель привязанной к старому session ID; она должна быть переключена на новый остановленный элемент либо очищена до следующего выбора.
- При повторном выборе чат/терминал создаётся с новым ID, сохранённым CWD/историей терминала и перенесённым контекстом.

### 6. Интерфейс
- `F2` запускает переименование выбранного элемента; при отсутствии выбора ничего не делает.
- Контекстное меню содержит `Rename` для папок, чатов и терминалов.
- В поле переименования показывается текущее имя, чтобы его можно было отредактировать.
- Ошибка конфликта или миграции отображается в том же модальном окне без закрытия операции.

## Критерии приёмки
- [x] `F2` открывает переименование выбранной папки, чата и терминала.
- [x] Контекстное меню запускает тот же rename-flow для всех трёх типов.
- [x] Конфликт имени или slug-сессии выдаёт ошибку, не объединяет данные и не меняет исходное дерево.
- [x] Переименование папки не меняет реальный `BoundPath`.
- [x] При переименовании папки сохраняются и находятся по новым ID notes, планы, status, jobs, Kanban и chat JSONL всех потомков.
- [x] При переименовании чата/терминала сохраняются его session data; у соседних элементов данные не затрагиваются.
- [x] Заголовок каждого перенесённого JSONL содержит новый session ID, история сообщений не меняется.
- [x] Familiars останавливаются, их контексты и JSONL сохраняются, а их новые IDs соответствуют новому владельцу.
- [x] При переименовании папки останавливаются все рабочие потомки; при переименовании отдельного элемента — только выбранный элемент и его familiars.
- [x] После повторного выбора переименованный чат/терминал запускается с новым ID и видит сохранённый контекст.
- [x] Нет старых каталогов сессий/domains после успешной миграции и нет целевых каталогов при отказе из-за конфликта.
- [x] `gofmt`, `go vet ./...`, `go test ./... -count=1` и `go build -o automata .` проходят.
