# Надёжный список активных jobs

## Контекст

Агент после длинной работы или потери контекста не может получить список собственных активных фоновых jobs: доступны только операции по известному ID. Правая панель Automata иногда показывает неактуальный список, потому что кеш отслеживает только изменение каталога `jobs/`, но не изменения вложенных `job.json`.

Текущая очистка удаляет jobs только по возрасту. Нужен дополнительный предел истории: не более 40 завершённых jobs на чат. Работающие jobs удалять нельзя независимо от возраста и количества.

## Цель

Добавить агенту tool для получения активных jobs текущего чата, гарантировать их отображение в правой панели и ограничить историю каждого чата 40 последними завершёнными jobs.

## Что изменится

1. `/Users/a/.ai/just/pi/extensions/job/index.ts` — получение активных jobs текущей сессии, новый tool и безопасная очистка истории.
2. `/Users/a/.ai/just/pi/extensions/job/index.test.mjs` — регрессионные тесты tool и очистки.
3. `/Users/a/.ai/just/pi/extensions/job/spec.md` — документация нового tool и правил очистки.
4. `internal/ai-knowledge/jobs/reader.go` — корректная инвалидация кеша при изменении вложенных `job.json`.
5. `internal/ai-knowledge/jobs/reader_test.go` — регрессионные тесты списка и кеша.
6. `CONTEXT.md` — запись найденной проблемы и решения.

## Детали реализации

1. Зарегистрировать tool `job_list` без параметров.
2. Получать ID текущего чата через `ctx.sessionManager.getSessionId()` и читать только каталог `jobs/` этой сессии.
3. Для каждой записи со статусом `running` проверять существование процесса. Мёртвый процесс помечать `exited` и не возвращать.
4. Возвращать активные jobs в стабильном порядке от новых к старым. Для каждой job возвращать ID, PID, время запуска, рабочий каталог и команду. Если активных jobs нет — возвращать явное сообщение `No active jobs`.
5. При очистке обрабатывать jobs отдельно для каждого чата:
   - никогда не удалять записи со статусом `running`;
   - среди завершённых сохранять 40 самых новых по `startedAt`;
   - удалять более старые завершённые записи независимо от их общего возраста;
   - недельную очистку применять только к завершённым jobs.
6. В `CachedReader` Automata вычислять ключ кеша по состоянию каталога и всех вложенных `job.json`, чтобы создание, завершение и изменение статуса job становились видны при очередном обновлении правой панели.
7. Не изменять формат существующих `job.json` и поведение `job_status`, `job_logs`, `job_stop`.

## Критерии приёмки

- [x] `job_list` возвращает только активные jobs текущего чата.
- [x] Jobs других чатов и профилей не попадают в ответ.
- [x] Завершившийся процесс исключается из ответа и помечается `exited`.
- [x] Running jobs не удаляются по возрасту или количеству.
- [x] На чат сохраняется не более 40 завершённых jobs.
- [x] Правая панель замечает изменение вложенного `job.json` без перезапуска Automata.
