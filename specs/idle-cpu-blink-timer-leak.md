# Устранение роста CPU при простое Automata

## Контекст

`App.Init` запускает первую цепочку `blinkCmd`, которая должна раз в секунду отправлять `blinkMsg` и планировать только одного наследника.

Сейчас дополнительные независимые цепочки создаются в двух местах:

1. `KnowledgeRefreshMsg` планирует новый `blinkCmd`, хотя исходный `blinkMsg` уже запланировал продолжение цепочки.
2. `tea.WindowSizeMsg` планирует новый `blinkCmd` при каждом изменении размера окна.

Из-за этого число секундных таймеров постоянно растёт. Простаивающий процесс `automata --profile Getic` после трёх часов работы стабильно потребляет 110–115% CPU. Профиль показывает непрерывные циклы `Bubble Tea eventLoop → App.View → Warp.View`.

## Цель

Гарантировать существование ровно одной цепочки `blinkCmd` на экземпляр Automata, чтобы потребление CPU не росло со временем при простое.

## Что изменится

1. `main.go` — убрать создание дополнительных `blinkCmd` из обработчиков `KnowledgeRefreshMsg` и `tea.WindowSizeMsg`.
2. `main_view_test.go` — добавить regression-тесты владения blink-цепочкой.
3. `CONTEXT.md` — записать проблему и решение в формате журнала ошибок проекта.

## Детали реализации

1. В обработчике `tea.WindowSizeMsg` возвращать только команду, полученную от `a.warp.Update(msg)`, без `tea.Batch(a.blinkCmd(), ...)`.
2. В обработчике `ui.KnowledgeRefreshMsg` применить обновление knowledge и вернуть `nil`, не создавая новый таймер.
3. Не менять обработчик `blinkMsg`:
   - обычный tick планирует ровно один следующий `blinkCmd`;
   - tick обновления knowledge планирует `RefreshKnowledgeCmd` и ровно один следующий `blinkCmd`.
4. Добавить тест, подтверждающий, что `KnowledgeRefreshMsg` не возвращает команду таймера.
5. Добавить тест, подтверждающий, что `tea.WindowSizeMsg` не оборачивает результат Warp в дополнительный batch с blink-таймером.
6. Не останавливать работающие пользовательские экземпляры Automata. Для проверки CPU собрать отдельный бинарник и запустить отдельный изолированный профиль.

## Критерии приёмки

- [x] `KnowledgeRefreshMsg` не создаёт `blinkCmd`.
- [x] `tea.WindowSizeMsg` не создаёт `blinkCmd`.
- [x] `blinkMsg` остаётся единственным владельцем продолжения blink-цепочки после `Init`.
- [x] Regression-тесты воспроизводят старую утечку и проходят после исправления.
- [x] `gofmt`, `go vet ./...`, `go test ./...` проходят.
- [x] `go build -o automata .` проходит.
- [x] Отдельный свежий экземпляр Automata сохраняет низкий CPU при простое; текущие пользовательские процессы не останавливаются.
