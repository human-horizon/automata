# Логи запусков Action-кнопок

## Контекст

Кнопка Action запускает команду и не сохраняет её вывод: раннер `runShellAction` в `internal/ui/actions_runner.go` отправлял stdout и stderr в `io.Discard`. Агент, который зарегистрировал действие тулом `add_action`, не знал, где искать результат запуска. Тул `add_action` (Pi, `/Users/a/.ai/just/pi/extensions/automata/index.ts`) регистрировал действие и возвращал только имя.

## Цель

Каждый запуск Action-кнопки пишет stdout и stderr в один и тот же известный файл для этого действия. Агент узнаёт путь из описания тула `add_action` и из результата регистрации.

## Что изменится

1. `internal/ai-knowledge/actions/reader.go` — функция `LogPath` рядом с `Directory`; записи действий по-прежнему читаются только из `*.json`.
2. `internal/ui/actions_runner.go` — раннер открывает файл лога, пишет заголовок и вывод команды.
3. `internal/ui/knowledge_actions.go` и `knowledge_panel.go` — путь лога передаётся при запуске, ошибка лога попадает в статус.
4. `/Users/a/.ai/just/pi/extensions/automata/index.ts` — описание `add_action` содержит схему пути; результат тула содержит абсолютный путь лога и `details.logPath`.
5. Тесты: Go (`actions_runner_test.go`, `internal/ai-knowledge/actions/reader_test.go`) и Pi (`extensions/automata/index.test.mjs`).
6. `CONTEXT.md` — запись о решении.

## Детали реализации

1. Путь лога: `<dataHome>/profiles/<profile>/domains/<domain>/actions/logs/<actionId>.log`, где `actionId` — тот же SHA-256 ID действия, что и имя его JSON-записи. Каталог `logs` создаётся с правами `0700`, файл — `0600`.
2. Режим записи (утверждено): каждый запуск перезаписывает файл. В начале пишется заголовок: время запуска, имя действия, рабочий каталог и команда. Затем идёт stdout и stderr команды. Отдельный лимит размера не вводится.
3. Файл лога не становится записью действия: `ReadForProfile` читает только `*.json` в каталоге `actions`, каталог `logs` игнорируется.
4. Ошибка открытия или записи лога не блокирует запуск команды: она попадает в статус панели как предупреждение, символическая ссылка и не-обычный файл как путь лога отклоняются.
5. Тул `add_action` в описании объясняет схему: лог перезаписывается при каждом запуске, абсолютный путь возвращается в результате регистрации.
6. Результат `add_action` содержит строку `Log: <абсолютный путь>` и `details.logPath`.
7. Подтверждение запуска, отмена, подсветка и перенос текста не меняются.

## Критерии приёмки

- [x] Запуск кнопки создаёт или перезаписывает `actions/logs/<actionId>.log` с заголовком и выводом команды.
- [x] Повторный запуск перезаписывает тот же файл, а не создаёт новый.
- [x] Ошибка записи лога показывается предупреждением, команда выполняется.
- [x] `ReadForProfile` не принимает `logs/` как запись действия.
- [x] Описание `add_action` содержит схему пути; результат тула содержит абсолютный путь лога.
- [x] Права каталога `0700`, файла `0600`.
- [x] Тесты Go и Pi проходят; `gofmt`, `go vet`, `golangci-lint`, полный `go test ./...` и race проходят.
- [ ] Коммит не создаётся; после пересборки бинарник обновлён, процессы перезапускает пользователь.
